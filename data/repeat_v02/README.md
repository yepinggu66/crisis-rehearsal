# data/repeat_v02 — the v0.2 evidence pack

Everything needed to recompute the numbers in the README without spending a single API
call. 30 public crisis events, each rehearsed 3 times: 90 full runs, 2 simulation
rounds per run, one LLM judge scoring every run with the same rubric as v0.1.

```
scores.jsonl         90 judge records, one per run (the raw evidence for 82.2%)
scores_v01.jsonl     30 judge records from the v0.1 single-run backtest (paired baseline)
item_clusters.json   LLM item merge used by the STA stability metric
ci_summary.md        generated by scripts/ci_stats.py  (deterministic, do not edit by hand)
sta_summary.md       generated by scripts/sta_stats.py (deterministic, do not edit by hand)
```

## Recompute, three commands, no API key

```bash
python scripts/ci_stats.py --out data/repeat_v02    # 82.2%, 95% CI 78.5-85.9, variance, 17%
python scripts/sta_stats.py --out data/repeat_v02   # stability STA 58 (pass line 60)
python scripts/cluster_items.py --out output_v2     # only needed to re-derive item_clusters.json
```

The first two run on the standard library alone (numpy is used for the bootstrap when it
happens to be installed; there is a pure-Python fallback). The third one calls an LLM to
re-merge risk items, which is why the merged result is shipped as a file you can inspect
instead of being recomputed behind your back.

## Record schema (`scores.jsonl`, one JSON object per line)

| Field | Meaning |
|---|---|
| `id` | Event id, 1–30, joins to `data/events.csv` and `data/seeds/{id}.md` |
| `run` | Repeat index, `"1"`–`"3"` |
| `name` | Chinese event name, copied from the event library at scoring time |
| `md5` | First 10 hex chars of the md5 of the report excerpt that was judged (7,000 chars). Lets you spot a rescored or replaced report; the full reports are not shipped |
| `top3` | The judge's three ranked risks: `rank`, `risk` (the report's own wording), `hit` (`yes` / `partial` / `no`), `why` (the judge's justification against the real outcome) |
| `path_hit` | Whether the report's propagation path matches the real key nodes (`yes` / `partial` / `no`) |
| `early_warning` | Early-warning quality, 0–100; missing for a couple of runs where the judge omitted it |
| `comment` | One-sentence overall verdict from the judge |

Scoring rule: `yes` = 1, `partial` = 0.5, `no` = 0, so one run scores 0–3. The headline
`82.2%` is the mean over events of the per-event mean score, divided by 3. It is a graded
score, **not** a binary hit rate, and the 90 runs are not 90 independent samples — the
statistical unit is the 30 events.

`scores_v01.jsonl` uses the same schema minus `run` and `md5` (one run per event). It is
the baseline for the paired per-event replication check (`-0.02/3 ±0.18`).

## Provenance

- Events: 30 publicly documented Chinese corporate crises, 2018–2026 (`data/events.csv`,
  outcomes and penalties included). Seed packs: `data/seeds/{id}.md`, T-72h information only.
- Engine: MiroFish (upstream, AGPL-3.0) with the local graph adapter in `patches/`,
  7–12 persona agents on a simulated Twitter/Reddit, 2 rounds per run.
- Judge: same model family as the simulator (`deepseek-chat`), temperature 0.2, JSON mode,
  fixed Chinese prompt (kept byte-identical to v0.1 so the two batches are comparable).
  See `scripts/score_repeat.py`.
- Runs: 2026-10-25/26, ~4 minutes and ~$0.03 per run.

## What this directory does *not* contain

- The 90 generated rehearsal reports (~8.4k characters / ~23 KB each). Only the judge's
  scoring of them is shipped, plus three full sample reports in `docs/reports/{1,25,28}.md`.
  You can recompute every published statistic, but you cannot independently re-judge the
  scores — and we say so in the README rather than implying otherwise.
- Human calibration of the judge. Spot checks are in progress and are not part of 82.2%.
