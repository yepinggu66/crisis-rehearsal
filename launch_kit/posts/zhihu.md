## 正文

如果你是一家公司的公关、IR、风控或应急负责人，大概都经历过这种时刻：事情在周五晚上爆出来，周末两天所有人都在等「第一份对外口径」，而真正的信息是碎片、互相矛盾、并且每小时都在变。

危机咨询行业卖的大多是**事后**的监测与响应。但在事情发生**之前**，其实可以做一件事：把危机预演一遍。

我们做了一个开源工具（危机预演 / Crisis Rehearsal），核心动作是：**把一起真实发生过的企业危机，倒回到它爆发前 72 小时，只给模拟器当时「已经公开」的信息，让一群 AI 角色去反应，产出一份预演报告，再拿报告里的前三大风险去对真实结局打分。**

### 一、我们具体做了什么

1. **30 起公开记录的中国企业危机（2018–2026）**。每一起都配一份 T-72h 信息包：只包含事发前 72 小时内公开可得的信息（媒体报道、公告、社交平台讨论等），形成一个「信息洁净室」。这一点很关键——如果用事后信息，回测就变成作弊。
2. **群体模拟**。每起事件 7–12 个 persona（记者、散户、监管、做空机构、竞争对手、消费者等），在模拟信息流里互动 2 轮，由 LLM 驱动。
3. **预演报告**。每次运行产出一份约 8k 字的结构化演练报告：时间线、利益相关方、升级阶梯、Top-3 风险、决策建议。
4. **评分**。一个固定的 LLM judge，用固定的 prompt 和阈值，把报告的 Top-3 风险与仓库里记录的真实结局对照，给出 0–3 分。
5. **90 次重复**。30 起事件 × 每起 3 次 = 90 次完整运行，同一套种子、同一套评分，用来估计「同一事件重跑会有多大波动」。

### 二、数字，以及数字必须带的限定

先说结论：**前三大风险命中率 82.2%，95% 置信区间 78.5–85.9**。

但这句话必须补充三个限定，否则就是误导：

- 它是 **event-mean graded score**：30 个事件每个 0–3 分，取事件均值（均值 2.47/3），**不是**二值命中率，也**不是**对下一个危机的概率预测。
- 90 次运行**不是 90 个独立样本**。统计单元是 30 个事件，重复跑是为了估计运行噪声。
- 置信区间只覆盖抽样与运行随机性，**不包含 judge 误差**；judge 也还没有做人工校准。

v0.1 是每个事件只跑一次、报 83%。v0.2 把每个事件重跑三次之后，结果变成 82.2%，与 v0.1 的配对差是 **−0.02/3（±0.18）**——旧结论复现了。这是整个项目里最不刺激、但我们最想写下来的一句话。

### 三、失败的部分（这段比数字重要）

重复跑暴露了一个不好看的事实：

- **只有 5/30（17%）的事件在三次运行里完全一致**。也就是说，同一事件跑两次，可能得到明显不同的报告。
- 组内标准差 **0.26/3**，中位数 0.24；而事件之间的难度差（组间 SD）是 0.30/3——**重跑带来的抖动，几乎和「不同事件本身难度不同」一样大**。
- 我们自己的稳定性指标 **STA 58**，自设及格线 60、资金线 75。**不及格。**这个数字写在 README、写在 `data/repeat_v02/v02_summary.md`，没有藏。
- 最主要的错误模式是「**过度升级**」：模型很爱写「监管介入 / 法务追责 / 甩锅供应商」这类分支，读起来很专业，但真实结局里并没有发生。在表现最差的 5 个事件里，6 个零分的 Top-3 席位有 5 个属于这一类。

还有两个更根本的限制：**没有对照组**（没和人类分析师比过，所以 82.2% 不能解释成「比人强」）；**2 轮模拟是对真实舆论动力学的简化**（它够用来产生升级路径和正确的问题，但不是社会的模型）。

### 四、所以这东西到底有什么用

对企业来说，它的价值不在那个 82.2%，而在它**强迫你在危机前产出的东西**：

- 一份带时间线的 T-72h 信息包；
- 一张利益相关方与升级阶梯图；
- 一份可以上会讨论的预演报告（自包含 HTML，可直接归档或发给董事会）；
- 以及在预演里提前暴露的分歧——这些分歧在真出事时，往往是最贵的。

我们的交付规则也因此写成：**同一事件跑 3–5 次，读共识，不看单次最好成绩。单跑单事件的分数是噪声。**

### 五、自己验证：一条命令，离线，不用 API key

我把所有证据都放在了仓库里：90 条 judge 原始记录、v0.1 基线、失败案例、评分脚本。你不需要 MiroFish、不需要模型 key，就能复算上面每一个数字：

```bash
pipx install git+https://github.com/yepinggu66/crisis-rehearsal
crh demo --out demo
```

`crh demo` 会做三件事：校验证据包 sha256（`crh verify`）、复算已发布统计（`crh stats`）、生成 4 份自包含 HTML 演练档案和索引页。**全程离线，无 API key，10 秒内。**

如果你要完整重建整个回测（90 次模拟），需要 MiroFish + 一个 LLM key（我们用 DeepSeek，约 $0.03/事件、~4 分钟/次，90 次大约 6 小时墙钟）。完整路径在 README 的 Reproduce it 一节。

### 六、企业版与政府版：我们有什么、没有什么

有：离线/私有化部署说明、三种部署形态（离线证据工作站 / 私有云 / air-gap）、场景包 schema（按行业/部门定制）、自包含 HTML 档案、证据 sha256 溯源。

没有，而且不会假装有：**没有客户案例，没有政府案例，没有任何认证。** 等保 2.0、数据安全法、个人信息保护法、GDPR、ISO 27001、SOC 2 的文档只是「要求映射 + 缺口清单」，不是测评结论；审计日志、RBAC、多租户目前是设计说明而不是已交付功能。这些在仓库文档里逐条写明了。

代码是 AGPL-3.0。我们卖的是演练报告与工作坊，不是软件许可。

### 七、最后

我把这套东西开源，不是因为它已经足够好，而是因为它足够**可被检验**：数字可复算、失败可查看、方法可反驳。
