# 即刻短帖（3 版）

> 平台调性：短、具体、有现场感；少形容词；可以自嘲。链接放评论区或正文末尾，避免「营销号」观感。
> 发布节奏：D2 发第一条，D12 发第二条，第三条约一周后随数据更新发。

---

## 版 1（发布日/次日，产品向）

```text
我们把 30 起真实企业危机倒回 72 小时前，让 7–12 个 AI 角色（记者、散户、监管、做空机构）只拿当时公开的信息，在模拟信息流里反应两轮，产出预演报告，再拿报告的前三大风险去对真实结局打分。

30 起 × 3 次 = 90 次回测，命中率 82.2%（95% CI 78.5–85.9）。

不好看的部分也一起开源了：只有 17% 的事件三次跑完全一致，我们自己的稳定性指标 STA 58，及格线 60——不及格。

一条命令自己验，离线、不用 API key、10 秒内：

pipx install git+https://github.com/yepinggu66/crisis-rehearsal
crh demo --out demo

（AGPL-3.0，证据都在仓库里）
```

## 版 2（诚实数字向，适合被转发）

```text
大多数 AI 项目发布时只给你看最好看的那次结果。

我们把 90 次回测的原始评分、失败案例、以及「我们自己没及格」的稳定性分数一起开源了。

82.2% 的命中率背后：17% 的事件能完全复现，组内标准差 0.26/3，最大的错误模式是「过度升级」——把没发生的法律/监管路径写进 Top-3。

危机预演这东西，如果只展示成功，等于在骗要拿它上董事会的人。

https://github.com/yepinggu66/crisis-rehearsal
```

## 即刻发布注意

| 项 | 做法 |
|---|---|
| 形式 | 纯文字 + 1 张图（终端截图或社交预览图）；不要长图海报 |
| 链接 | 正文放一次即可；即刻外链不会像公众号那样被折叠，但连续发链接会被判定推广 |
| 圈子 | 发在「AI」「独立开发」「创业」相关圈子；同一内容不要跨 5 个圈子刷 |
| 互动 | 有人问「怎么用」就回一条命令 + 一句限制；不引导加微信 |
| 频率 | 每周 ≤2 条；连续三条都在推同一仓库会掉粉 |
| 禁止 | 抽奖/集赞/「转发抽」；编造用户反馈 |
